Descripción detallada

El test 'Validar que se muestren todas las curvas esperadas' falló al intentar localizar el elemento de carga '.ball-loader' (línea 598 de commands.js). La duración total de 96s indica que se agotó el defaultCommandTimeout de 90s. El screenshot y el DOM al momento del fallo muestran la interfaz completamente cargada con la lista de curvas visible, lo que sugiere que el spinner desapareció antes de que Cypress intentara capturarlo o que el selector ya no existe.

Posibles causas

ALTA
Race condition por carga rápida
El HAR muestra solo 3 requests y ninguna lenta. Si la API responde en milisegundos, el componente '.ball-loader' puede desmontarse antes de que el comando cy.get lo encuentre.
MEDIA
Cambio de selector en la UI
Si la versión v1.44.6 reemplazó '.ball-loader' por otro componente (ej. 'placeholder-glow'), el test fallará por timeout al buscar un selector inexistente.
ALTA
Lógica de espera estricta en commands.js
El stack trace apunta a un comando custom que probablemente hace un cy.get('.ball-loader').should('exist') sin contemplar que la carga ya haya finalizado.

Pasos de Troubleshooting

1 Reproducir localmente con: TARGET_ENV=production TARGET_CLIENT=argentina SPEC=sanity_curvas npm run test
2 Revisar la implementación del comando en 'cypress/support/commands.js' línea 598.
3 Verificar si el selector '.ball-loader' sigue presente en el código fuente de la aplicación (frontend).
4 Modificar la lógica de espera para que sea condicional o use un elemento que persista (como el título de la sección).
5 Ejecutar el test con 'cy.pause()' para observar el ciclo de vida del spinner manualmente.
