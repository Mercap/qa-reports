Descripción detallada

El test ejecutaba el flujo de validación de cotización intradiaria para el bono AL30 dentro del módulo de Sensibilidad. El fallo ocurrió al intentar verificar que el menú desplegable de búsqueda de especies desapareciera tras la selección. Según el error y el DOM de fallo, el elemento '.dropdown-menu.show' continuó presente con las opciones AL30, AL30D y AL30C visibles, agotando el timeout de 10000ms de la aserción 'not.exist'.

Posibles causas

ALTA
Bug de UI en componente SecuritySearchInput
El DOM de fallo muestra el input con el valor 'AL30 - BYMA - ARS' ya cargado, pero el div hermano '.dropdown-menu' sigue teniendo la clase 'show' y contiene los elementos de búsqueda, lo que indica que el evento de cierre no se disparó o falló.
MEDIA
Condición de carrera en la aserción
El test valida la inexistencia del dropdown inmediatamente después de la selección. Si la animación de cierre o el re-renderizado del componente es más lento que la ejecución de Cypress, la aserción falla aunque el cierre esté en proceso.
BAJA
Falta de evento blur o click-away
El foco podría haber quedado atrapado en el input de búsqueda, impidiendo que el componente interprete que la interacción de selección ha finalizado completamente.

Pasos de Troubleshooting

1 Reproducir el fallo localmente: TARGET_ENV=production TARGET_CLIENT=argentina SPEC=cotizaciones-intradiarias_02_check-intraday-quotes-abbaco npm run test
2 Verificar manualmente en producción si al seleccionar AL30 en el modal de Sensibilidad el dropdown se cierra consistentemente.
3 Inspeccionar el archivo cypress/support/commands.js en la línea 1885 para identificar la lógica exacta de la aserción fallida.
4 Verificar si el componente SecuritySearchInput en v1.46.7 recibió cambios recientes que afecten el manejo del estado del dropdown.
