Descripción detallada

El test 'Eliminar todos los escenarios' falló en la línea 36 del flujo de sensibilidad al realizar una aserción sobre el contenido de una celda <td>. Según la evidencia del video (01:38) y el DOM de fallo, la especie agregada a la tabla es 'TX28', pero el test espera encontrar el texto 'AL30'. El error persiste durante los 90 segundos del defaultCommandTimeout, lo que indica que no es un problema de carga lenta, sino de datos incorrectos en la UI respecto a la expectativa del script.

Posibles causas

ALTA
Lógica de test inconsistente
El video muestra la búsqueda y selección de 'TX28', pero el error de Cypress indica que la aserción en la línea 36 busca explícitamente 'AL30'. Es un error de mantenimiento del script.
MEDIA
Estado residual de la aplicación
Si el test anterior no limpió correctamente la tabla de sensibilidad, 'TX28' podría estar ocupando la primera posición de la tabla donde el test espera encontrar la especie recién agregada.
BAJA
Cambio en el orden de respuesta de la API
Si el test busca el primer elemento de la tabla y la API de Mercap cambió el orden de las especies devueltas, la aserción fallará si no es dinámica.

Pasos de Troubleshooting

1 Reproducir el fallo localmente con: SPEC=build/production/argentina/flows/smoke/sensibilidad.js npm run cy:open
2 Verificar la línea 36 del archivo sensibilidad.js para confirmar si el string 'AL30' está hardcodeado.
3 Inspeccionar el paso previo a la aserción para ver qué especie se está ingresando en el componente 'SecuritySearchInput'.
4 Validar si el test requiere una limpieza previa de la tabla de sensibilidad antes de agregar nuevas especies.
5 Ejecutar el test en modo encabezado para observar si la selección en el dropdown coincide con la intención del test.
