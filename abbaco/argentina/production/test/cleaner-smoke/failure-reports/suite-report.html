Descripción detallada

El test 'Eliminar todos los escenarios' falló en la línea 36 al intentar validar que el bono en la tabla fuera 'AL30'. Según la evidencia del DOM y el mensaje de error, la aplicación cargó y mostró correctamente el bono 'TX28', lo que provocó que la aserción fallara tras agotar el timeout de 90 segundos. El hecho de que el último test exitoso del mismo run también mostrara 'TX28' sugiere una inconsistencia en la lógica de validación del script o un cambio en el ticker utilizado en los pasos previos del flujo.

Posibles causas

ALTA
Ticker hardcodeado en el test
El script de test en la línea 36 espera específicamente el texto 'AL30', pero el flujo previo o el estado de la cuenta en producción cargó 'TX28'.
MEDIA
Persistencia de estado en la sesión
La sesión de Abbaco (cy.session) podría estar manteniendo un bono agregado en una ejecución anterior o por otro test, interfiriendo con la expectativa de este spec.
BAJA
Cambio en resultados de búsqueda
Si el test selecciona el primer resultado de búsqueda al agregar una especie, un cambio en el orden de la API de Mercap podría haber devuelto TX28 en lugar de AL30.

1 Reproducir el fallo localmente: TARGET_ENV=production TARGET_CLIENT=argentina SPEC=build/production/argentina/flows/smoke/sensibilidad.js npx cypress run
2 Revisar el video del test para identificar en qué momento se agregó el bono 'TX28' y si el buscador devolvió ese resultado por error.
3 Verificar en el archivo sensibilidad.js si el ticker 'AL30' está hardcodeado en la línea 36.
4 Ejecutar el test limpiando cookies y localStorage para descartar persistencia de estado: npm run cy:open y usar 'Clear All' en la tabla de sensibilidad manualmente.
