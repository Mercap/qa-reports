Error 404 en DELETE de portafolio — 'Portafolio Cypress Modificado' persiste en UI tras fallo de red

Descripción detallada

El flujo de eliminación del portafolio falló al intentar verificar que el elemento desapareciera de la pantalla. Según el HAR, la solicitud DELETE a la API de Mercap devolvió un status 404 (Not Found) en 157ms. Como el backend no procesó la eliminación, el frontend mantuvo el componente visible en el DOM, lo que provocó que Cypress agotara el timeout de 90000ms esperando que el texto 'Portafolio Cypress Modificado' dejara de existir.

Posibles causas

ALTA
Error 404 persistente en API
La evidencia de red muestra un fallo explícito 404 al intentar eliminar el ID 5d21e7f1-fe18-0e00-b665-820e0b3f15a8, lo que indica que el recurso no existe o el ID es incorrecto.
MEDIA
Falta de manejo de errores en el Frontend
La UI no reaccionó al error 404 de la API (por ejemplo, mostrando un toast o revirtiendo el estado), dejando el elemento 'huérfano' en el DOM y rompiendo la aserción del test.
BAJA
Race condition en persistencia
El portafolio podría haber sido creado en un nodo de base de datos que aún no había replicado al nodo consultado por el proceso de eliminación.

1 Reproducir el fallo localmente: TARGET_ENV=production TARGET_CLIENT=argentina MODE=only SPEC=smoke/portafolio npm run test
2 Verificar manualmente en el ambiente de producción si el portafolio 'Portafolio Cypress Modificado' sigue visible para el usuario de test.
3 Ejecutar un GET https://api.mercapabbaco.com/portfolios/ con el token de sesión para confirmar si el ID 5d21e7f1-fe18-0e00-b665-820e0b3f15a8 figura en la lista oficial.
4 Revisar los logs de la API de Mercap para identificar por qué el DELETE devolvió 404 (ej: desincronización de caché o borrado lógico previo).
5 Validar en el código del frontend si existe un bloque .catch() que maneje fallos en la eliminación de portafolios.
