Descripción detallada

El test 'Eliminar los portafolios creados' falló prematuramente a los 8.7s debido a un error de socket cerrado durante la ejecución de un callback de intercepción de red. El DOM de fallo confirma que la aplicación quedó bloqueada en el estado de carga inicial (ball-loader). La captura de pantalla revela un bloque de texto extremadamente extenso (posiblemente un JWT o JSON base64) en el log de Cypress, lo que sugiere que una respuesta de API saturó el buffer del proxy de red.

Posibles causas

ALTA
Payload de API sobredimensionado
El error 'Socket closed before finished writing response' en un interceptor suele ocurrir cuando el volumen de datos de la respuesta excede la capacidad de procesamiento del proxy de Cypress, especialmente en Firefox. El screenshot muestra un string masivo que refuerza esta hipótesis.
MEDIA
Inestabilidad de red en el ambiente de producción
Un micro-corte de conexión durante la transferencia de datos entre el servidor de Mercap y el runner de Cypress puede provocar el cierre abrupto del socket antes de completar la escritura de la respuesta.

Pasos de Troubleshooting

1 Reproducir el fallo localmente: TARGET_ENV=production TARGET_CLIENT=argentina SPEC=cleaner.cy.js npm run test
2 Inspeccionar el archivo HAR para determinar el tamaño exacto de la respuesta del endpoint /security-position o el que contenga el string masivo visto en el screenshot.
3 Verificar si el usuario de QA tiene acumulados cientos de portafolios de ejecuciones previas que deban ser eliminados manualmente para reducir el tamaño del payload.
4 Revisar el uso de cy.intercept() en el spec para evitar el procesamiento de cuerpos de respuesta pesados si no es estrictamente necesario para la lógica del test.
