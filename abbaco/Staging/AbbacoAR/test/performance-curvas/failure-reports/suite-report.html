Descripción detallada

El fallo ocurre en el hook 'before all' durante la ejecución de cy.SessionAbbaco(). El stack trace indica que el error se originó en 'procesarLogin' (commands.js:133) al intentar localizar el elemento '.ball-loader'. La screenshot muestra que la aplicación ya se encuentra en el dashboard ('Inicio'), lo que sugiere que el loader desapareció antes de que Cypress pudiera capturarlo o nunca se renderizó debido a una carga rápida. Se observan múltiples errores 404 en la consola para el endpoint de favoritos, aunque el error principal es de sincronización de UI.

Posibles causas

ALTA
Race condition en validación de login
El comando cy.get('.ball-loader') falla porque el elemento ya no está en el DOM cuando Cypress intenta buscarlo, ya que la página de Inicio cargó exitosamente (visible en screenshot).
MEDIA
Cambio en el flujo de navegación
Una actualización reciente en Staging (v1.45.3) podría haber eliminado el loader intermedio durante el proceso de autenticación.
BAJA
Interferencia por errores 404
Los fallos recurrentes en el endpoint /favorites/yieldCurve podrían estar afectando el ciclo de vida de los componentes de carga, aunque la UI parece funcional.

Pasos de Troubleshooting

1 Reproducir localmente apuntando a staging: TARGET_ENV=staging TARGET_CLIENT=argentina npm run cy:open
2 Verificar en commands.js (línea 133) si el cy.get('.ball-loader') tiene un timeout explícito o si debería ser opcional.
3 Inspeccionar el flujo manual de login en Staging para confirmar si el spinner '.ball-loader' sigue siendo parte de la transición.
4 Revisar logs de red para confirmar si los errores 404 en favoritos están bloqueando la ejecución de scripts posteriores.
5 Aumentar la verbosidad de los logs de Cypress para capturar el momento exacto de la transición de URL.
