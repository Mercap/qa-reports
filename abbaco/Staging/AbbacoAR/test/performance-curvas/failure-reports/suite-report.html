Timeout 90s en login: selector .ball-loader no encontrado en hook de sesión (staging)

Descripción detallada

El test falla en el hook 'before all' durante la creación de la sesión mediante cy.SessionAbbaco(). El stack trace indica que el comando finalizarSesion (commands.js:99) agotó el timeout de 90s esperando el spinner '.ball-loader'. Sin embargo, la screenshot muestra que la aplicación ya cargó el Dashboard (Home), lo que sugiere que el loader ya desapareció o el flujo de login lo omitió por completo. Se observan múltiples errores 404 en el endpoint de favoritos en la consola de Cypress.

Posibles causas

ALTA
Cambio de UI en Staging
La versión v1.45.3 podría haber eliminado o reemplazado el componente '.ball-loader' durante el proceso de login/redirección.
MEDIA
Race condition en la detección del loader
La aplicación cargó tan rápido que el spinner apareció y desapareció antes de que Cypress ejecutara el comando cy.get('.ball-loader'), causando el timeout al buscar un elemento que ya no existe.
BAJA
Errores de API (404)
Los fallos recurrentes en 'api.staging.mercap.com.ar/.../favorites/yieldCurve' podrían estar alterando el ciclo de vida de la carga, aunque la UI parece haber renderizado el dashboard correctamente.

Pasos de Troubleshooting

1 Reproducir el fallo localmente: TARGET_ENV=staging TARGET_CLIENT=argentina SPEC=performance_curvas.cy.js npm run test
2 Inspeccionar el archivo 'cypress/support/commands.js' en la línea 99 para verificar la lógica de espera del loader.
3 Verificar manualmente en el navegador si el selector '.ball-loader' sigue existiendo durante el proceso de login en staging.
4 Revisar si hubo cambios recientes en el componente de carga en el repositorio de la aplicación web.
5 Validar con el equipo de backend por qué el endpoint de favoritos devuelve 404 para el usuario de test.
