Timeout 90s en Screener — No se encontró 'button.accordion-button' por estar en modo 'Screener IA' en lugar de Manual

Descripción detallada

El flujo 'Screener > Ingresar al menú Screener' falló al intentar localizar un elemento de tipo acordeón en la interfaz. El fallo ocurrió tras agotar el timeout de 90000ms, lo que indica que el elemento nunca llegó a renderizarse. La evidencia del screenshot y el DOM confirman que la aplicación se encuentra en el modo 'Screener IA' (marcado como 'NUEVO' y con el input 'screener-mode-ia' con atributo checked), el cual utiliza una interfaz de chat y no contiene los botones de acordeón típicos del modo Manual.

Posibles causas

ALTA
Cambio de vista predeterminada a Screener IA
El DOM muestra el input 'screener-mode-ia' como seleccionado por defecto. El screenshot muestra la interfaz de chat de IA en lugar de los filtros manuales. Los elementos 'button.accordion-button' pertenecen exclusivamente a la vista Manual.
MEDIA
Falta de paso de selección de modo en el test
El script en la línea 14 de 'screener.js' intenta acceder directamente a un filtro sin asegurar previamente que el modo 'Screener Manual' esté activo.
BAJA
Selector de Bootstrap desactualizado
Aunque es posible un cambio de clases en una actualización de dependencias, la ausencia total de la estructura de filtros en el DOM apunta a un error de navegación/estado.

Pasos de Troubleshooting

1 Reproducir el fallo localmente: TARGET_ENV=production TARGET_CLIENT=argentina npx cypress run --spec **/screener.js
2 Verificar manualmente si al ingresar a /bond-screener la aplicación activa el modo IA por defecto.
3 Inspeccionar el código del test en 'flows/performance/screener.js:14' para confirmar si existe un comando .click() sobre '#screener-mode-manual'.
4 Validar si el componente de acordeón ha cambiado su clase CSS en la rama de desarrollo actual.
5 Revisar el HAR para confirmar que no hubo errores de carga en los assets de la vista manual (aunque el reporte indica 0 fallos de red).
