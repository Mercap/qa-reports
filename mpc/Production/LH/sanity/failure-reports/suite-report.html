Descripción detallada

El test "Ingresar y hacer login en el admin de MPC" intentaba autenticarse en el panel de administración de MPC. El fallo ocurrió durante la redirección post-autenticación, donde la aserción esperaba que la URL incluyera 'https://laholando.mercapportfolio.com/mercap-portfolio-admin'. En su lugar, el navegador permaneció en una página de error de Auth0 ('https://mercap.auth0.com/authorize/resume?...') que devolvió un código de estado 400, mostrando los mensajes "Oops!, something went wrong" y "Failure when querying database". La aserción agotó su timeout de 180 segundos esperando la URL correcta.

Posibles causas

ALTA
Problema de configuración/base de datos de Auth0
El HAR muestra un `GET https://mercap.auth0.com/authorize/resume?...` con status 400. El DOM y el screenshot confirman una página de error de Auth0 con el mensaje "Failure when querying database", lo que sugiere un problema interno de Auth0 o su conexión a la base de datos.
MEDIA
Credenciales de login incorrectas o expiradas
Un error 400 en Auth0 puede ser causado por credenciales inválidas o un estado de sesión corrupto, aunque el mensaje "Failure when querying database" apunta a un problema más profundo en el servicio de Auth0.
BAJA
URL de callback de Auth0 incorrecta
Si la URL de callback configurada en Auth0 para el ambiente `laholando` fuera incorrecta, podría generar un error de redirección. Sin embargo, el error 400 con "Failure when querying database" es más específico de un problema de backend de Auth0.

Pasos de Troubleshooting

1 Verificar el estado del servicio de Auth0 para Mercap y el ambiente `production/laholando`.
2 Reproducir el spec localmente: `TARGET_ENV=production TARGET_CLIENT=laholando MODE=only SPEC=sanity.cy.js npm run metrics-x-spec`
3 Verificar manualmente el login al admin de MPC en `production/laholando` usando las credenciales configuradas.
4 Revisar los logs de Auth0 para el `TRACKING ID: 0f14d5a3c437e42cc405` mencionado en el DOM del fallo.
