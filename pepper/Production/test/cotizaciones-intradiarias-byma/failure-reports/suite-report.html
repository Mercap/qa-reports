Descripción detallada

El test 'Login > Ingresar y hacer login' intentó autenticarse, pero fue redirigido a una página de error de Auth0 (mercap-admin-test.us.auth0.com) en lugar de la aplicación. La UI de la aplicación no se renderizó, mostrando en su lugar un error 'Oops!, something went wrong' con el detalle 'invalid_request' de Auth0. El test falló porque el comando utilitario no encontró la UI esperada tras varios reintentos, como se observa en el video y el DOM al momento del fallo.

Posibles causas

ALTA
Auth0 'invalid_request'
El DOM al momento del fallo y el screenshot muestran claramente el mensaje de error 'invalid_request' de Auth0, indicando un problema con la solicitud de autenticación o la sesión.
MEDIA
Configuración de ambiente/cliente
El test se ejecuta en 'production/arg-gs32' (que típicamente usa login directo GS32), pero la URL y el error provienen de Auth0 (usado para GS64). Esto sugiere una posible misconfiguración que redirige a un flujo de autenticación incorrecto.
MEDIA
Problema de cookies/sesión
El mensaje de error de Auth0 menciona explícitamente 'issue with cookies, since we couldn't find your session', lo que es una causa común para este tipo de 'invalid_request'.

Pasos de Troubleshooting

1 Verificar la configuración de TARGET_ENV y TARGET_CLIENT para 'production/arg-gs32' y confirmar si debe usar Auth0 o login directo.
2 Reproducir el spec fallido localmente con 'TARGET_ENV=production TARGET_CLIENT=arg-gs32 MODE=only SPEC=cotizaciones_intradiarias_byma npm run test' para observar el comportamiento en detalle.
3 Revisar los logs de Auth0 para el 'TRACKING ID: 5e2d84ef6ae569f44315' para obtener más detalles sobre el 'invalid_request'.
4 Limpiar cookies y caché del navegador antes de ejecutar el test, o usar cy.clearCookies() y cy.clearLocalStorage() explícitamente si no se hace ya.
5 Si el ambiente 'production/arg-gs32' *debe* usar Auth0, verificar las credenciales PEPPER_USER/PEPPER_PASSWORD y la configuración del cliente Auth0.
